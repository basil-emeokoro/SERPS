## Scope and method

This document preserves the pre-implementation repository baseline and records the verified completion outcome for the core multimodal checkpoint. It examines source, manifests, static assets, migrations, API contracts, frontend routes, tests and all Git history available in the authoritative repository. A dependency, diagram label or interface word is not treated as proof of operational inference.

The repository was searched for YOLO, Ultralytics, ONNX, TensorFlow, PyTorch, OpenCV, MediaPipe object detection, COCO labels, person/phone detection, bounding boxes, frame sampling, Web Audio, `AudioContext`, `AnalyserNode`, RMS, sound/voice activity, microphone lifecycle events and audio-visual correlation. Git history was also searched for the relevant modules and event names.

## Pre-implementation authoritative finding

No operational or dormant object-detection implementation was found. `src/serps_pop/vision/__init__.py` has contained only an architecture-boundary docstring since commit `8c6ac55`. Object detection appears in Chapter Three generation code and older status documentation only.

No operational or dormant audio-monitoring implementation was found. `src/serps_pop/audio/__init__.py` has contained only an architecture-boundary docstring since commit `8c6ac55`. The current candidate readiness flow requests camera and microphone permission together and records `microphone_available`, but it does not open a persistent audio-only stream, analyse samples, generate audio EvidenceEvents or correlate audio evidence. `docs/poc_to_pop_migration_audit.md` states that an earlier POC had an audio module that was not migrated; that earlier implementation is not present in this authoritative repository or its available branches/history.

The only operational local computer-vision capability is MediaPipe Face Landmarker for bounded identity enrolment/authentication. It is not an object detector and does not support mobile-phone or general scene-object classification.

## Existing reusable foundation

- `@mediapipe/tasks-vision` 0.10.35 and locally hosted MediaPipe WASM resources already support privacy-conscious browser inference without a mandatory external API.
- The authoritative `EvidenceEvent` API already enforces candidate ownership, active-session state, institution isolation, event/source allowlists and persistence.
- CIE assessments already persist score, risk level, confidence, explanation, event identifiers and rule version.
- Agentic recommendation, IPIME policy evaluation, reviewer authority, governance audit and structured reports are already operational for supported event types.
- Reviewer and administrator views are metadata-only and already disclose the absence of remote live video.

## Minimum implementation decision

Proceed with a bounded local-browser implementation:

1. MediaPipe Tasks Vision Object Detector with a locally stored, documented EfficientDet-Lite0 COCO model, an explicit confidence threshold, bounded video sampling and only `person`/`cell phone` outputs.
2. Web Audio API microphone acquisition with RMS-based normalised signal energy, bounded intervals, sustained-activity windows and cooldown-based duplicate suppression.
3. Extend the existing EvidenceEvent contract with privacy-safe structured metadata instead of creating a parallel event model.
4. Add deterministic CIE-RULES-2.0 handling for isolated, repeated, corroborated and unavailable states while keeping every recommendation advisory and every examination continuing.
5. Expose detector status and genuine event metadata in candidate, reviewer and administrator interfaces without fabricating feeds or detections.

This decision does not authorise claims of biometric-grade recognition, general prohibited-object detection, speech understanding, speaker identification, certified accuracy, production readiness or misconduct determination.

## Verified completion outcome

MediaPipe Tasks Vision 0.10.35 now loads the locally hosted EfficientDet-Lite0 COCO float32/1 model and samples browser video every 1.5 seconds at a configurable 0.55 default threshold. The browser audio monitor uses Web Audio RMS energy at 200 ms intervals, a configurable 0.08 threshold, a 600 ms activity window, a 2,500 ms sustained window and a 10-second duplicate cooldown. Neither raw video nor raw audio is persisted by default.

The Edge runtime returned HTTP 200 for local model/WASM assets, started the graph without failed requests, acquired the physical integrated camera at 640×480 and 30 fps, and persisted `person_detected` events at 0.781 and 0.7506 confidence. It acquired the physical Realtek microphone and displayed live RMS values. The active session retained a stale identifier for a disconnected USB camera, so normal workspace acquisition correctly reported permission denied; a controlled diagnostic attached the available integrated camera to isolate session selection from inference health. Physical multiple-person, phone-present and threshold-crossing audio observations were not performed.
